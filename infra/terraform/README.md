# Reference infrastructure: ECS Fargate, RDS, S3

This module describes how RequestDesk would run on AWS. It is committed, formatted and validated
in CI, and **deliberately not applied**: the public demo runs on Fly.io for a few dollars a month,
and an RDS instance plus a NAT gateway would cost more than the demo is worth. The point of the
module is that the shape is written down and checked, not that it is billing anyone.

What it builds:

- A VPC across two availability zones. Public subnets for the load balancer, private subnets for
  everything else, one NAT gateway for outbound traffic from the private side.
- An application load balancer. `/api/*`, `/health*`, `/openapi/*` and `/scalar*` route to the API
  service; everything else routes to the nginx front end.
- Two Fargate services in one ECS cluster, with CloudWatch logs and container health checks.
- PostgreSQL 17 on RDS in the private subnets, encrypted, with seven days of backups.
- A private, versioned, encrypted S3 bucket for attachments, and a task role that may touch that
  bucket and nothing else.
- Two Secrets Manager secrets, the connection string and the JWT signing key, generated by
  Terraform and referenced by ARN from the task definition. Their values never appear in state
  outputs, the console's task definition view, or this repository.

What it leaves out, on purpose: HTTPS (add an ACM certificate and a 443 listener with a redirect
once there is a domain), autoscaling, a bastion, and a remote state backend. Each is a small, well
known addition; none of them changes the shape.

```sh
terraform init
terraform plan \
  -var api_image=ghcr.io/eric-patton/requestdesk-api:latest \
  -var web_image=ghcr.io/eric-patton/requestdesk-web:latest
```

The API reads `Storage__Root` for local-disk attachments today. The S3 implementation of
`IFileStorage` is the swap that would make `Attachments__Bucket` live; it is listed under "what I
deliberately did not build" in the main README.
